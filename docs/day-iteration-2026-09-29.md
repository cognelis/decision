# 2026-09-29 评审迭代记录

围绕“评审”页的一组改动，逐轮合入 `main` 并替换本机 App。前半段按用户的具体要求推进，后半段（新加坡时间 22:17 起，到 24:00 止）按目标“用 Claude Design 优化界面并持续迭代”自主推进。

## 第 1 轮：PR 快照按提交缓存并在后台预读（`1228fd3`）

每次切换 PR 都要重新读取变更内容。参照 `code-meeseeks` 的做法（本地 git 镜像、轮询时后台同步、按提交判断是否需要重拉），做了不需要复制仓库的版本：

- 快照按源/目标提交对缓存：同一对提交的 diff 不会变。内存保留最近 20 个，并写入本机 `pr-review-cache`（最多 60 个），重启后仍在。
- 打开读过的 PR 先立即显示缓存，再用 1 个请求核对提交；没变就直接可用，有新提交才重读 diff。
- PR 列表的更新时间变了而提交没变时只重读已有评论；手动输入的引用没有列表时间可比，也重读评论；上次读评论失败的下次再试。
- 列表加载后在后台依次预读前 5 个 PR，更新时间没变的不发请求，遇到 401/403/429 立即停止，评审进行中不预读。
- 同一提交的文件内容只下载一次，评审翻页与文件查看器共用；只缓存读完的内容，停止评审不会连带让文件查看器失败。

## 第 2 轮：核对提交不再闪出忙碌状态（`74a4278`）

用户反馈切换 PR 时会闪一下“正在核对最新提交”。除了这句提示，核对期间整个面板还会被禁用变暗、提示行插入又移除导致内容跳动，并且核对期间点别的 PR 会被吞掉。

- 读过的 PR 在后台静默核对：不显示提示、不禁用任何控件，只有发现新提交或核对失败才提示。
- 核对期间可以直接切到下一个 PR，上一个 PR 迟到的核对结果按 generation 丢弃。
- 核对期间点“开始评审”会先等核对完成，再评审平台确认的最新提交；平台操作在主进程按固定提交校验，不受影响。
- 面板切换一步完成，不经过空白或“重试读取”的中间状态。

## 第 3 轮：回答里的表格与分隔线（`6a7352e`）

“PR 概览”要求输出逐文件说明表，但回答渲染器原本不支持表格和 `---`，表格被挤成一段竖线与横线。按用户本机一条真实回答的结构确认后补上 GFM 表格（行内格式、`\|` 转义、缺格补空、紧跟段落的表格）与分隔线；宽表在回答内横向滚动。评审与助手两个页面共用这个渲染器。

## 第 4 轮：不评审也能生成 PR 概览与改进建议（`db1e778`）

这两个指令原本接在评审后的追问上，请求必须带评审报告，所以只能在历史评审里用；概览还会混入报告内容，并复述提示词里的约束。

- 追问请求的评审报告改为可选；没有报告时用专门的提示词，只带 PR 快照、描述、diff 与命中的团队规则。
- 约束改成指令式写法，并要求不在回答里复述。
- 结果存为历史评审里的一条“问答记录”（`kind: "chat"`，旧记录默认按评审解析），可继续追问和导出。
- 追问带上连接 ID：重启后内存里没有快照时，从本机快照缓存找回同一对提交的 diff。

## 第 5 轮：用 Claude Design 重做评审准备页（`b2534cd`）

截图看出准备页的问题：中间大片空白；Approve / Need work / Merge 这类高风险平台操作排在最显眼的第一行且是英文；规则、已有评论、批次都是灰色小字；刚加的 PR 概览、改进建议只是两个小链接。

先在 Claude Design 画布上出稿（“Decision 评审准备页”），再按稿实现：

- 平台操作移到标题行右侧，改为“批准 / 需要修改 / 合并”；评审记录视图同样处理，对话区更高。
- “这次会带上”：变更文件、命中规则（可直接管理规则）、已有评论、批次四格统计。
- “选择方式”：完整评审 / PR 概览 / 改进建议三张单选卡片（`fieldset` + `legend`），写明用途与调用次数；输入框只保留一个主按钮，文字随所选方式变化。
- 浅色与深色都截图核对过，布局溢出检查通过。
- 之后补了一处：不计为已审查的文件、被跳过的规则等提示改为警示底色的提示条，不再是和正文一样的灰色小字。

## 第 6 轮：问答记录的收尾（`a171ff8`、`0e4d548`）

- 问答记录里的操作不再沿用评审说法：“评审最新提交”“导出记录”“删除记录”，删除确认与导出提示同步调整。
- 从问答记录回到准备页时默认切回“完整评审”，因为看完概览的下一步通常是完整评审。
- 准备页的关注点输入框支持 ⌘ / Ctrl + Enter 直接运行所选方式（与问答页一致）；问答记录显示当时填写的关注点。

## 第 7 轮：删除连接时清掉它的缓存（`752c849`）

磁盘缓存保存 PR 的 diff 原文，原先删除平台连接后，这些文件要等缓存超过 60 个才会被挤掉。

- 缓存文件名以连接 ID 开头，删除连接时按前缀清掉磁盘文件，同时丢弃内存里该连接的快照。
- 按旧命名写入的缓存文件不会再被读取，下次写入缓存时直接清除。

## 第 8 轮：回答可以复制（`c20d54f`）

pr-agent 的 `/describe` 会直接更新 PR 描述；这里坚持不自动写平台，改为每条追问 / 问答回答旁边提供“复制”，复制的是 Markdown 原文，贴进 PR 描述即可。

## 第 9 轮：用方向键浏览列表（`1ac4873`）

读过的 PR 切换已经是即时的，PR 列表与历史列表里用 ↑/↓ 移动焦点并打开相邻一项，列表底部提示“↑↓ 切换”。

## 第 10 轮：准备页显示 PR 描述（`ae64c94`）

PR 描述原先只在“查看 PR 详情”弹窗的折叠区里。现在准备页最上方直接显示（短描述默认展开，长描述可展开并在框内滚动，按安全的 Markdown 子集渲染）；没有描述时提示可以先生成 PR 概览，并提供“选择 PR 概览”一键切换方式。

## 第 11 轮：历史里找得到问答记录（`2c21f88`）

「历史评审」的搜索也匹配记录类型，输入“概览”就能找回之前生成的 PR 概览；评审页的空状态提示也补上了“可以先生成 PR 概览或改进建议”。

## 第 12 轮：从问答记录一步进入完整评审（`8cfb2e7`）

问答记录原先只能通过标题行的刷新图标回到准备页，不容易发现。现在输入框工具栏在“PR 概览”“改进建议”旁边多了“完整评审”，和图标共用同一段逻辑：读取最新提交并把方式切回完整评审。

## 第 13 轮：向下浏览时提前预读（`1ecd4e6`）

列表加载时只预读前 5 个 PR，用 ↓ 走到后面就又要完整读取。现在打开某个 PR 时，顺带在后台预读它后面的两个；新一轮预读会接替上一轮，列表时间没变的 PR 不发请求。

## 第 14 轮：大 PR 的概览不再超长失败

追问回答上限 8000 字（历史记录按同一上限校验），文件很多的 PR 生成逐文件说明表时容易超出，结果是“回答失败”且重试也一样。没有放宽上限（要同时改协议、历史格式和输出 token），而是在 PR 概览指令里要求文件多时按目录或模块合并、表格不超过 20 行、全文 3000 字以内。

## 仍有的限制

- 没有本地 git 镜像，平台单次响应最多 2 MiB，超大 PR 的 diff 读不全。
- 文件状态是各平台的原始字符串，准备页的文件统计暂不按新增 / 删除分类。
- 评审追问框是 Enter 发送，问答页是 ⌘ / Ctrl + Enter 发送；两处的发送键不同，改动会影响已有习惯，暂未统一。
