- 交付：方法论 → 分析顶部新增「周期回顾」，近 7 天 / 近 30 天切换，窗口为今天及此前的自然日：

## 第 15 轮：第二次独立审查

再派审查代理通读第 8–14 轮的 18 个提交（共用下拉的结论/进度互斥、初始标签页的消费时机、同题查询的竞态、IPC 边界均核查无误），报出两处真实缺陷，均已修复并补了会在修复前失败的测试：

- `7d564d0`（高）项目下钻用 SQLite `trim(d.project)` 比较，它只去 ASCII 空格，而回顾按 JavaScript `trim()` 归组。捕获与手动记录两条写入路径都会先 trim，但笔记是事实来源，在 Obsidian 里手改出尾部全角空格或 Tab 后重建索引，回顾里有记录、下钻却是空列表。现在把 JavaScript 的完整空白字符集作为 `trim(x, ?)` 的参数，两边语义一致。
- `ab86856`（中）详情「已复制为 Markdown」的提示只按记录 id 显示，关闭后重开或切走再切回同一条会无故重现（`role=status` 还会被读屏重播）。切换记录时清空。

## 已知边界与后续

- 「复制为 Markdown」与「整理交接」同样依赖 `navigator.clipboard`，窗口失焦时会失败并提示。
- 周期回顾的「反复出现的问题」只按问题文字归组，不做语义合并；表达差异大的同类问题不会被归到一起。
- 待补理由仍不支持「只选依据」补全；若需要，应在存储层增加不含原文的补全形态，而不是拼接依据充当原文。
- 「以前也回答过这个问题」与回顾的重复问题同一规则，只认文字相同的问题（忽略大小写、全半角、空白与句末标点）。
- 预期结果写下后在结果出来之前可以修改，但不能清空；「稍后处理 / 跳过」时理由面板里写的预期与理由原文一样不会保留。
- 回顾里的「待写预期」只数窗口内新建的决策；更早的未决决策请直接用知识页「待写预期」筛选（不限时间）。
- 项目下钻只在从回顾进入时出现，知识页没有独立的项目下拉。
