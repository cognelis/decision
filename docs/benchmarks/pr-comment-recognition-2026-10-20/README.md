# PR 评论决策识别评测（2026-10-20）

## 结论

- 默认推荐 **Claude Code CLI（haiku）**。在没参与调参的盲测集上，它的精确率 0.85、召回 0.88、F1 0.87；单次调用中位 8.8 秒，token 用量也最省。
- Codex CLI（gpt-6-luna）可用，但漏得多：盲测召回 0.69、F1 0.75。它每次调用自带很长的客户端提示词，输入 token 是 haiku 的 3 倍多。
- 本机 Qwen3.5-4B 不适合这个任务：精确率 0.36、召回 0.13；274 条里有 79 条没判出结果，多是摘句不在原文里，或者编号对错了评论。
- DeepSeek（OpenAI 兼容 API）没有评测：命令行评测器不从应用的密钥库读取 API 密钥。

## 样本与标注

- **来源**：公司内部 Bitbucket Server 上真实的 PR，分布在 4 个仓库，全部是本人评审或创建的 PR。用 bitbucket-cli 只读拉取讨论串（含回复关系）。原文只放在已忽略的 `out/` 目录，没有提交；本目录只有汇总数字和语料的 SHA-256。
- **调参集**：24 个 PR，646 条评论。其中 330 条来自评审机器人和 CI 的两个账号，识别时跳过，只作上下文；人写的 316 条里，标为决定 64 条、拿不准（maybe）42 条。
- **盲测集**：另外 12 个已合并的 PR，232 条评论，人写的 118 条，标为决定 26 条、maybe 25 条。标注在跑任何模型之前完成，提示词 v2 定稿之后才跑这批，没有再按它的结果改提示词或标签。
- **标注者**：只有一位（Claude），没有第二位标注者。maybe 不计入精确率和召回，只统计被判成决定的条数。
- **标注口径**（和提示词一致）：
  - 算决定：在几种做法里选定一种；评审者明确要求的做法或规范；约定以后怎么做；明确不做、先不做、推迟或缩小范围（对机器人提的问题只回「不处理」也算）；对提议拍板的那条回复。
  - 不算决定：提问、商量、标了「不阻塞」「个人意见」的建议；修复说明；说明问题不成立；只解释现状；只影响一处的修修补补；机器人消息。

## 方法

`scripts/evaluate-pr-comment-recognition.mjs` 用 Vite 加载应用里正式的识别代码（`pr-comment-recognition.ts` 的分批、提示词和校验）和 `ProfiledModelGateway`，用本机已登录的 CLI 或本机模型逐批调用，再和单独存放的标签对比。分批规则和应用一致：

- 远端模型和 CLI 每次最多 15 条待判断评论、约 1.4 万字符；本机模型每次 4 条、约 2400 字符。
- 回复和它所在讨论串的其他评论放在一起，其他评论只作上下文。
- 模型给出的摘句必须能在这条评论原文里找到，否则这条结果不算数（记为「没判」）。

调用超时统一放宽到 120 秒，调用之间串行。

## v1 → v2 改了什么

v1 的误报和漏报各有集中的几类，v2 的提示词逐条写明了它们算不算决定：

- **误报**：
  - 详细的修复说明，例如「已修：……」，以及复核后说「已修复」。
  - 说明问题不成立，例如「不改代码：……不会漏」。
  - 标了「不阻塞，可以之后处理」的建议。
  - 把提议本身当成决定。应该算的是同意它的那条回复。
- **漏报**：
  - 评审者明确的要求，例如「应该避免没有租户 ID 的查询」「禁止 ... 加三元的写法」。
  - 对机器人提的问题只回一句「不处理」。

盲测里 haiku 剩下的误报，主要是对一处细节的附和（「嗯对」）和对现状的解释。漏报是很短的要求（「用 token」）和「过度防御」这类回复。

## 局限

- 只有一位标注者，maybe 占人写评论的 13%–21%，口径本身有主观成分。
- 样本只来自一个团队、一个平台，评论都是中文。GitHub、GitLab 的评论习惯可能不同。
- 单次运行，没有重复跑来估计模型输出的波动。
- 没有评测 DeepSeek。如需比较，在应用里选它做识别模型，到「模型调用记录」里看结果。

## 复跑

```sh
npm run evaluate:pr-comments -- run --cases out/pr-comment-recognition/2026-10-20/holdout-cases.json \
  --profile-id builtin-claude-code --timeout-ms 120000 --skip-authors <机器人账号,CI账号> \
  --output out/pr-comment-recognition/2026-10-20/holdout-run.json
npm run evaluate:pr-comments -- score --run out/pr-comment-recognition/2026-10-20/holdout-run.json \
  --labels out/pr-comment-recognition/2026-10-20/holdout-labels.json --cases out/pr-comment-recognition/2026-10-20/holdout-cases.json
```

`--profile-id` 取 `model-provider-profiles.json` 里的配置，只支持 Qwen 和 Codex、Claude Code 两个 CLI。运行会把评论正文交给对应的模型服务。
