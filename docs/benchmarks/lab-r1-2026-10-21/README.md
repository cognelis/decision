| 识别语料 36 条：high 精确率 / high+medium 召回 | 0.917 / 0.481 | 1.000 / 0.556 |

保留集按类别比较（固定文本，每类 10 条，main → 最终）：
- 显式批准识别 0 → 5，拒绝 4 → 8，批准加追问 3 → 6；
- 「仅确认收到」的误报 5 → 0；
- 「转移话题」的误报不变，都是 2；
- **部分批准退化**：main 能识别 3 条，最终版 0 条。这几条回复对应的助手消息没有抽出选项，回复里对其余选项又用了推迟说法，于是被「推迟」压成 low。根因在选项抽取，见文末限制。

两次 App 实跑之间的差异来自模型每次的措辞不同（同一批原文在两版规则下判定一致），同一批原文在两版规则下的对比才是规则本身的效果。

**对抗样本。** 反例代理和审查代理按代码推理构造，合成样本共 104 条：main 精确率 0.64、召回 0.45；最终版 0.88、0.91。

## 已知限制（留到下一轮）

- 选项抽取不完整：`**A. …**` 这种加粗写法、每个选项单独成段的写法，选项都抽不出来。真实对话中识别正确的 40 条里，有 33 条选项为空。选项为空时，部分批准最多只能到 medium；如果其余选项用了推迟说法，还可能被压成 low。保留集里的部分批准因此从 main 的 3/10 降到 0/10，这是本轮唯一一个类别级退化。
- 仍会漏识别的写法：
  - 「请选 A、B 或 C」；
  - 以「跳过/略过」开头的免责段；
  - 问句和建议分成两段、中间还夹着免责段。
- 「1 上次用过」这类陈述历史事实的分句，可能被当作决定。
- 「转移话题」在保留集里仍有 2/8 误报。
- 保留集的识别召回只有 0.556，规则方式本身有上限。
