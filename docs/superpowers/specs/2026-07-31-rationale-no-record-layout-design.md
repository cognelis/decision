# Decision “不记录”布局与提交稳定性设计

日期：2026-07-31

状态：已确认，待实现

## 1. 背景

理由岛固定使用 `560 × 400` 窗口。用户勾选“不记录此次决策”后，理由表单被移除，
但窗口和玻璃背景仍保持 400px 高。实际预览测量显示：

- 正常理由表单的操作区底部为 378.6px，底部留白约 21.4px；
- 勾选“不记录”后，操作区底部变为 209.2px，底部留白约 190.8px；
- 若先展开上下文再勾选，操作区底部为 235.2px。

点击“不记录”提交时，理由队列会先发布 `completed/saving` 快照。当前窗口管理器把所有
`completed` 状态切换为普通面板，因此窗口会先从 `560 × 400` 动画放大到
`560 × 640`，随后在持久化完成后隐藏，形成一次明显抽动。

## 2. 目标

- 勾选“不记录此次决策”后，将理由岛收缩到与确认内容匹配的高度；
- 取消勾选后恢复完整理由表单高度；
- 展开的上下文在紧凑状态仍不被裁切；
- 点击“不记录”后直接关闭可见窗口，不执行 400px 到 640px 的中间动画；
- 若持久化失败，仍显示现有错误面板和“重试保存”操作；
- 不允许 renderer 传入任意窗口尺寸，不改变其它窗口模式。

## 3. 方案比较

### 3.1 固定的语义化紧凑模式

新增 `island-rationale-compact` 窗口模式，尺寸固定为 `560 × 256`。renderer 只能请求
“紧凑”或“完整”两种理由状态，主进程决定实际尺寸。该高度覆盖展开上下文后的
235.2px 内容，并保留约 21px 底部安全边距。

优点是权限边界清晰、尺寸确定、原生玻璃圆角与窗口模式能保持同步，测试也稳定。采用。

### 3.2 renderer 上报实时内容高度

使用 `ResizeObserver` 测量 DOM，再通过 IPC 把像素高度交给主进程。能得到最小留白，
但会暴露任意 resize 接口，且字体、动画和异步布局可能造成连续微调和新的抖动。不采用。

### 3.3 保持 400px 并填充确认说明

保留窗口尺寸，用大块提示或禁用后的原表单填满区域。实现最少，但无关内容仍占空间，
没有解决窗口与当前任务密度不匹配的问题。不采用。

## 4. 详细设计

### 4.1 窗口模式

在共享布局定义中新增：

- `ISLAND_RATIONALE_COMPACT_SIZE = { width: 560, height: 256 }`；
- `DecisionWindowMode` 值 `island-rationale-compact`。

紧凑模式与完整理由岛一样固定在工作区顶部，并使用底部圆角的原生玻璃表面。

`WindowManager` 增加窄接口 `setRationaleCompact(compact: boolean)`。它只在当前理由岛
模式生效，只调整固定模式的 bounds 和原生表面，不重复调用 `show()` 或 `focus()`。
这样勾选控件不会因窗口重新聚焦而闪动。

窗口管理器记录当前模式和当前理由候选 ID。候选改变、进入设置、进入候选审核、显示普通
面板或隐藏窗口时，紧凑状态重置，避免下一个候选继承上一个候选的“不记录”尺寸。

### 4.2 renderer 与 IPC

`DecisionApi` 新增：

```ts
setRationaleCompact(compact: boolean): Promise<void>;
```

preload 只暴露这一布尔接口。主进程 IPC 使用严格的 `z.boolean()` 校验后调用窗口管理器，
不接收宽度、高度或坐标。

`RationaleStep` 在“不记录此次决策”复选框变化时：

1. 立即更新本地 `doNotRecord` 状态；
2. 通知 App 请求对应窗口模式；
3. resize 请求失败时保持表单功能可用，不把非关键窗口错误显示成保存错误。

取消勾选时恢复 `560 × 400`。

### 4.3 提交期间

`WindowManager.publish()` 收到：

```text
current.status = completed
persistenceStatus = saving
```

时立即隐藏窗口，不改变 bounds，不切换到普通 panel，也不更新原生表面模式。

后续结果：

- 保存成功：队列发布 `current = null`，窗口保持隐藏；
- 保存失败：队列发布 `persistenceStatus = failed`，窗口按现有 `560 × 640` 面板显示错误和
  重试按钮；
- 重试保存期间再次隐藏，失败则重新显示。

“记录理由”“稍后处理”“跳过理由”同样受益于提交期间不放大，但其数据和队列行为不变。

## 5. 测试

测试先行覆盖：

1. 共享布局定义包含 `560 × 256` 紧凑尺寸；
2. IPC 只接受布尔紧凑请求，并正确转发；
3. renderer 勾选和取消勾选时分别请求紧凑与完整模式；
4. Electron 布局测量器在展开上下文的“不记录”状态下确认内容底部不超过 256px；
5. `WindowManager` 切换紧凑模式时只设置 bounds，不重复 show/focus；
6. `completed/saving` 快照只隐藏，不触发 `560 × 640` bounds；
7. `completed/failed` 快照仍显示普通错误面板。

完成定向测试后运行全量测试、类型检查、打包和桌面冒烟验证。

## 6. 非目标

- 不改变“不记录”需要复选框加确认按钮的二次确认流程；
- 不改变理由持久化或恢复协议；
- 不改变设置页模型列表加载抖动问题；
- 不引入任意窗口 resize API；
- 不调整其它窗口的尺寸、圆角或定位。
