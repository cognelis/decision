# Decision 设置与外观重设计

日期：2026-07-24

状态：已实现并完成验收

适用版本：Electron 43 / macOS 首发版

## 1. 背景

现有设置窗口采用 560 × 640 的纵向卡片布局，标题区和分组间留白过多，半透明外层又会让底层文字直接穿透，信息密度和质感都不符合 Decision 的产品方向。

菜单栏图标的左键事件还会绕过菜单直接打开设置。用户无法主动选择菜单操作。应用也只有深色配色，缺少跟随系统和手动主题偏好。

本次重设计在不改变决策记录、Obsidian 事实源和 SQLite 派生索引的前提下，统一设置窗口、主题系统、菜单栏交互和品牌图标。

## 2. 目标

- 左键点击菜单栏图标只展开菜单，不直接打开设置。
- 把菜单项“打开设置”改为“设置”。
- 设置窗口更紧凑、清晰且具有真正的 macOS 半透明质感。
- 支持“自动、浅色、深色”三种主题偏好；自动模式实时跟随系统。
- 主题偏好跨重启保存，并兼容已有 v1 设置文件。
- 用一套 AI 融合字形覆盖 App、设置工具栏、菜单栏和极小尺寸。
- 所有普通操作按钮移除前置图标，形成一致的文字型软圆角控件。
- 让决策选择、理由追问和结果反馈界面与设置页使用同一套视觉语言。
- 保持现有 Electron 安全边界和非 macOS 平台的可用降级。

## 3. 非目标

- 不重做顶部决策小岛和理由收集流程的信息架构。
- 不改变 Markdown、SQLite 或 hooks/MCP 协议。
- 不引入云端主题、用户账号、皮肤市场或可自定义强调色。
- 不在本次工作中实现 Windows/Linux 安装包；只保证 CSS 降级不会阻断未来移植。
- 不引入一套通用图标库。设置按钮按用户要求只使用文字。

## 4. 菜单栏交互

macOS Tray 使用真实的单色模板图片，不再以标题字符 `◇` 充当图标。

菜单固定为：

1. `设置`
2. 分隔线
3. `退出 Decision`

`Tray.setContextMenu` 负责标准的左键和右键菜单行为。删除当前 `tray.on("click", openSettings)` 监听器，因此点击图标本身不会直接打开设置。只有选择菜单中的“设置”才调用 `controller.openSettings()`。

菜单栏使用 AI 字形的单色线性版本，并标记为 template image，使 macOS 根据浅色/深色菜单栏自动着色。极小尺寸不使用实心底形，避免缩成黑块。

## 5. 设置窗口布局

设置态窗口从共用的 560 × 640 面板中分离，使用约 680 × 430 的独立尺寸。内容溢出时窗口内部滚动，不继续扩大窗口。

`WindowManager` 新增 `settings` 模式和 `SETTINGS_SIZE`。现有 `island`（420 × 72）与复杂决策使用的 `panel`（560 × 640）保持不变，避免设置重设计意外压缩理由输入或长决策内容。

窗口模式选择顺序：

1. `snapshot.settingsOpen` 为真时使用 `settings`。
2. 没有当前决策时隐藏。
3. 满足紧凑条件的决策使用 `island`。
4. 其他决策继续使用 `panel`。

布局从上到下为：

### 5.1 紧凑工具栏

- 高度约 52px。
- 左侧显示 AI 标识、`Decision / 设置`。
- 右侧是关闭按钮。
- 不再使用独立的大号“设置”标题，也不重复显示居中标题。
- 工具栏空白区域保留拖动能力，所有按钮保持 `no-drag`。

### 5.2 状态摘要

三等分显示：

- 开发工具连接数量。
- SQLite 本地索引健康状态。
- 待补理由数量。

摘要只表达状态，不承载操作。健康状态同时使用文字与颜色，不只依赖颜色。

### 5.3 主内容区

采用约 3:2 的双栏：

- 左栏“通用”：主题偏好、Obsidian 仓库、全文索引。
- 右栏“开发工具”：Claude Code、Codex 连接状态和连接操作。
- 下方全宽“待补理由”：无待办时显示紧凑空状态，有待办时沿用现有补充理由能力并允许区域内部展开。

窄窗口降级为单栏，但首发 macOS 固定尺寸下默认显示双栏。

## 6. 视觉系统

### 6.1 原生材质

macOS BrowserWindow 使用 Electron 43 支持的：

- `transparent: true`
- `vibrancy: "under-window"`
- `visualEffectState: "active"`
- 透明窗口背景

外层由系统负责桌面背景模糊。Renderer 使用半透明表面、细描边、内侧高光和柔和阴影建立层级，不让底层内容以清晰文字直接穿透。

非 macOS 平台不设置原生 vibrancy，仅使用相同的半透明 CSS token 和 `backdrop-filter` 作为降级。

### 6.2 主题 token

Renderer 只通过语义变量使用颜色：

- 窗口材质
- 工具栏材质
- 内容表面
- 悬浮表面
- 弱/强边框
- 主文字、次文字、弱文字
- 强调色与强调色表面
- 健康、警告、错误状态
- 阴影与内侧高光

浅色主题使用冷浅灰玻璃和绿蓝强调色；深色主题保留低亮度深蓝灰材质，并降低背景穿透，保证可读性。两种主题都以绿色表达健康状态，但不把主题与业务状态混为同一变量。

CSS 使用 `prefers-color-scheme` 切换 token。Electron 的 `nativeTheme.themeSource` 决定媒体查询结果，所以自动和手动模式共享一套样式，不在 Renderer 复制主题判断逻辑。

主题 token 同时用于设置窗口和现有决策小岛/浮层，使主题切换覆盖整个 App；回答流程的信息架构和状态机保持不变，但所有可见表面和控件都纳入本次视觉统一。

### 6.3 按钮

所有普通操作按钮：

- 不显示前置图标。
- 使用文字标签。
- 使用软圆角胶囊形状和低对比半透明表面。
- 次级操作通过中性色表达。
- 主要操作通过浅强调色表面和强调色文字表达，不使用大面积不透明绿色。
- hover 只轻微抬升或提高表面对比度。
- focus-visible 保留清晰焦点环。
- disabled 同时降低对比度并禁用交互。
- 尊重 `prefers-reduced-motion`。

决策选项不是普通操作按钮：简短选项在小岛中保持紧凑胶囊形态，复杂选项继续使用可容纳说明和取舍的卡片形态。两者仍使用同一套表面、边框、圆角、焦点和动效 token，不套用设置页普通按钮的固定尺寸。

### 6.4 回答界面一致性

回答界面覆盖：

- 紧凑决策小岛。
- 展开的决策选项面板。
- 自定义答案输入。
- 理由追问与理由因素。
- 稍后补充、跳过、不记录和重试保存。
- 保存中、保存失败和空闲状态。

统一规则：

- 外壳使用与设置窗口相同的原生毛玻璃、半透明边界、内侧高光和阴影体系。
- `island`、`panel`、`settings` 三种窗口模式共享主题 token，但各自保留适合内容的尺寸与密度。
- 来源徽标、推荐标识和状态提示使用同一套语义色；推荐不能只依赖颜色表达。
- 选项卡片使用透明内容表面，hover/selected/recommended 状态通过边框、表面和轻微位移区分。
- 自定义回答、理由文本框和复选控件使用同一套半透明输入表面、焦点环和错误状态。
- 回答流程中的普通操作按钮遵循 6.3 的无前置图标规则。
- 小岛中长文字仍可省略，但问题、来源和推荐标识的视觉优先级保持明确。
- 深色主题提高内容表面不透明度，避免桌面背景影响长文本阅读。
- 从选择进入理由追问时不改变窗口视觉语言，也不产生主题闪烁。

本次只统一视觉呈现，不改变现有问题长度判断、紧凑/展开切换条件、选项语义、理由状态或持久化行为。

## 7. 品牌图标

品牌标识采用 `AI Living Mark`：

- `A` 使用向上生长的圆角骨架。
- 独立光点和竖线构成小写 `i`。
- 彩色版本使用绿色到蓝紫色的渐变，表达生命力和未来感。
- 单色版本保持同一线性骨架，用于 macOS 菜单栏。
- 极小尺寸增加线宽、保留负空间，不增加实心背景。

仓库保存可编辑的 SVG 母版，并导出：

- Renderer 使用的 SVG/React 组件。
- macOS App 图标所需的高分辨率位图和 `.icns`。
- 16px 与 32px Retina 菜单栏 template PNG。

图标导出物由同一母版生成，避免多套形状逐渐不一致。打包配置显式使用新的 App 图标。

## 8. 设置模型与迁移

新增主题类型：

```ts
type ThemePreference = "auto" | "light" | "dark";
```

设置文件升级为：

```ts
interface AppSettingsV2 {
  version: 2;
  vaultPath: string | null;
  theme: ThemePreference;
}
```

默认值：

```text
theme = auto
```

`SettingsRepository.load()` 同时接受 v1 和 v2：

- v1 原样保留 `vaultPath`，补充 `theme: "auto"`，返回内存中的 v2。
- v2 严格校验所有字段。
- 缺失设置文件返回 v2 默认值。
- 非法 JSON、未知版本或非法主题继续显式报错，不静默覆盖用户文件。

下一次正常保存会把迁移结果写成 v2。选择新 Obsidian 仓库、自动发现默认仓库以及通过 `DECISION_VAULT_PATH` 覆盖仓库时，都必须基于当前设置做不可变更新，不能把主题重置为默认值。

## 9. 主题状态与数据流

主进程是主题偏好的唯一所有者：

1. 启动时加载并迁移设置。
2. 在创建 BrowserWindow 前设置 `nativeTheme.themeSource`。
3. 把主题偏好放入 `AppSnapshot`。
4. Renderer 的三段式控件显示当前偏好。
5. 用户选择主题后调用收窄的 `setTheme(preference)` preload API。
6. IPC 使用 Zod 枚举校验输入。
7. 主进程先原子保存新设置，再更新内存状态和 `nativeTheme.themeSource`。
8. 保存成功后发布新 snapshot；保存失败则保留原主题并向 Renderer 返回错误。

映射关系：

```text
auto  -> nativeTheme.themeSource = "system"
light -> nativeTheme.themeSource = "light"
dark  -> nativeTheme.themeSource = "dark"
```

自动模式下系统外观变化由 Electron 更新 `prefers-color-scheme`，Renderer 无需额外 IPC。Snapshot 记录的是用户偏好，不是瞬时解析结果。

## 10. 接口变更

`AppSnapshot` 新增：

```ts
theme: ThemePreference;
```

`DecisionApi` 新增：

```ts
setTheme(theme: ThemePreference): Promise<void>;
```

新增专用 IPC channel：

```text
decision:set-theme
```

preload 只暴露上述枚举操作，不开放通用 IPC。预览 API 同步提供无副作用实现，保证本地 UI 预览仍可运行。

`AppController` 通过回调读取当前主题偏好，避免把启动时的值冻结在构造参数中。主题保存成功后复用当前 snapshot 发布机制刷新设置界面。

## 11. 错误处理

- 主题保存失败：控件恢复原值，并在设置窗口显示错误消息。
- 原生 vibrancy 不支持：窗口继续使用 CSS 降级，不影响操作。
- 图标资源读取失败：应用仍能启动；开发构建输出明确诊断，发布构建测试阻止缺失资产进入安装包。
- 自动主题切换：不得重载页面、丢失输入或改变设置窗口开关状态。
- 旧设置迁移：不得修改 vault 路径，也不得触碰 Markdown 或 SQLite 数据。

## 12. 安全与隐私

本次变更保持：

- `nodeIntegration: false`
- `contextIsolation: true`
- `sandbox: true`
- 只加载本地 Renderer
- preload 按能力暴露 API
- IPC 输入 schema 校验

主题偏好只保存在现有本地设置文件中，不引入遥测、网络请求或新的用户数据。

## 13. 测试策略

实施采用测试驱动方式。

### 13.1 设置与迁移

- 缺失文件返回 v2 + auto。
- v1 迁移保留 vault 路径并补充 auto。
- v2 的 auto/light/dark 往返保存。
- 非法主题和未知版本报错。
- 更换 vault 时不重置主题。

### 13.2 IPC 与 preload

- `setTheme` channel 正确注册与清理。
- 三个合法枚举值能传递给 operation。
- 任意其他输入在进入 operation 前被拒绝。
- preload 与公开方法白名单包含 `setTheme`，不暴露通用调用能力。

### 13.3 窗口与菜单栏

- 设置态使用新的 680 × 430 边界和独立 `settings` 模式。
- 复杂决策继续使用原有 560 × 640 `panel`，小岛继续使用 420 × 72。
- macOS 窗口选项包含原生 vibrancy 和活动视觉状态。
- 安全相关 BrowserWindow 选项不回退。
- Tray 不注册直接打开设置的 click handler。
- 菜单项文本为“设置”，并且只有菜单项调用 `openSettings`。

菜单创建逻辑应抽成可注入依赖的窄函数，避免在测试中启动真实 Electron App。

### 13.4 Renderer

- 三段式主题控件显示 snapshot 中的偏好。
- 点击其他主题调用 `setTheme`。
- 设置失败显示错误且不谎报成功。
- 状态摘要与双栏内容正确渲染。
- 小岛、展开选项、自定义回答、理由追问和保存状态均使用统一主题 class/token。
- 决策选项的紧凑胶囊与复杂卡片保持原有内容能力，并正确呈现推荐、焦点、禁用和错误状态。
- 所有设置操作仍可通过键盘访问。
- 设置页和回答流程中的普通操作按钮不渲染装饰性前置图标。
- 浅色和深色下的关键文字、焦点与状态满足可读性检查。

### 13.5 构建与真实验收

- 运行完整测试和 TypeScript 类型检查。
- 打包后的 App 包含 App 图标和两套 tray template PNG。
- 安装并启动真实 macOS App。
- 分别检查自动、浅色、深色模式。
- 切换系统主题，确认自动模式实时响应。
- 左键菜单栏图标，确认只出现菜单。
- 选择“设置”，确认窗口尺寸、毛玻璃、按钮、AI 图标和信息密度与确认稿一致。
- 分别走通预设选择、自定义回答、理由填写、稍后补充、跳过和保存失败重试，确认各回答界面与设置页风格统一。
- 重启 App，确认主题偏好保持。

## 14. 验收标准

满足以下条件才视为完成：

- 菜单栏左键不会直接打开设置。
- 菜单显示“设置”，选择后才打开窗口。
- 设置窗口不再出现大标题留白，默认尺寸约为 680 × 430。
- 自动、浅色、深色均可选择、立即生效并跨重启保存。
- 自动模式随系统主题变化。
- 浅色和深色都有可读的半透明质感。
- 设置按钮没有前置图标，主次层级协调。
- 回答小岛、展开选项、理由输入和反馈状态与设置页使用统一的材质、主题和控件语言。
- App 与菜单栏使用同源 AI 标识，极小版本不糊成黑块。
- 已有 vault 设置和所有决策数据保持不变。
- 完整测试、类型检查、打包和真实 App 验收通过。
