# Decision 连续待处理与透明毛玻璃设计

日期：2026-07-28  
状态：已确认
方向：连续单卡

## 背景

当前中置信度候选需要从菜单栏的“待确认候选”入口逐项处理。确认或忽略一项后，
主进程会主动关闭审核界面；当队列里还有其它项目时，用户必须回到菜单重新打开。

当前候选面板还存在两个体验问题：

- “待确认候选”是实现语言，不是用户任务语言；
- 大标题、识别状态和说明文字占用较多纵向空间，真正用于判断的原文、回答和上下文
  空间不足。

此外，窗口虽然已配置透明背景、macOS vibrancy 和 CSS blur，但浅色主题的高光叠层及
多层半透明表面叠加后接近不透明，设置、理由岛和候选面板的毛玻璃感也不一致。

## 目标

- 一次打开即可连续处理整个候选队列。
- 产品界面统一使用“待处理”，不再显示“待确认候选”。
- 把原文、用户回答和问题相关上下文作为页面主体。
- 保持“确认后补理由”的现有产品语义。
- Auto、Light、Dark 三种主题共享同一套透明毛玻璃材质层级。
- 在 macOS 桌面背景上能明显看到真实的透色和模糊，同时保证文字、焦点和操作可读。

## 非目标

- 不增加完整的决策历史、搜索、筛选或批量操作。
- 不把待处理页改成双栏收件箱或卡片滑动界面。
- 不改变候选的 7 天过期、容量、去重、确认回执或 Markdown/SQLite 原则。
- 不改变 Claude Code、Codex 的原生行为或 Hook 静默采集方式。
- 不为毛玻璃增加图片纹理、品牌插画或装饰性图标。

## 1. 术语

所有当前用户可见入口和状态统一替换为“待处理”：

| 位置 | 文案 |
| --- | --- |
| 菜单栏 | `待处理 N` |
| 设置摘要 | `待处理`、`N 项待处理`、`查看` |
| 面板无障碍名称 | `待处理决策` |
| 面板进度 | `待处理 X / N` |
| 暂停操作 | `稍后` |

“候选”和“中置信度”继续作为内部模型及诊断术语，但不占用主操作界面。

## 2. 连续处理会话

用户从菜单栏或设置页打开待处理面板后，进入一个连续处理会话。

### 2.1 队列推进

- **忽略成功**：保持当前窗口，立即显示 FIFO 队列的下一项。
- **记录成功**：当前候选提升为正式理由项，界面暂时进入该项的现有理由流程。
- **理由完成、跳过或稍后补充**：如果仍有候选，自动返回待处理面板并显示下一项。
- **最后一项处置完成**：自动关闭窗口。
- **新增候选**：会话打开期间进入队尾，进度总数随快照更新。

记录后的理由流程只临时挂起待处理会话；其它已有理由项不会丢失或被标记完成。

### 2.2 主动暂停

- 点击“稍后”、按 Escape 或关闭窗口只结束当前显示会话；
- 当前候选和剩余队列保持不变；
- 下次打开仍从最早未处理项继续；
- 暂停不是“忽略”，不生成处置回执。

### 2.3 保存失败

- 确认或忽略的持久化进行中时禁用操作；
- 失败时保留当前项、会话和原文，原位显示错误及“重试”；
- 重试成功后按原动作继续推进；
- 失败不得关闭窗口或跳到下一项。

## 3. 面板结构

待处理面板继续使用 560 × 640 普通面板和 12px 顶部安全距离，避免动态改变窗口尺寸
造成跳动。空间重新分配如下：

1. **紧凑工具栏，约 48px**
   - 来源徽标；
   - 项目名；
   - `待处理 X / N`；
   - “稍后”。
2. **判断正文，可滚动并占据主要空间**
   - 需要判断的问题；
   - 捕获到的决策原文；
   - 用户回答；
   - 问题相关上下文及展开入口。
3. **固定操作栏，约 64px**
   - 次操作“忽略”；
   - 主操作“记录并补充理由”。

删除以下内容：

- “本地识别 · 尚未写入 Obsidian”眉题；
- “这是一个需要记录的决策吗？”大标题；
- “确认后会进入理由采集……”说明段落；
- 重复表达相同状态的卡片标题和标签。

正文区至少获得除工具栏和操作栏之外的全部高度。短文本不人为放大留白；长文本在
正文区滚动，工具栏和操作栏保持可见。

## 4. 内容层级

### 4.1 问题

问题是正文首个标题，但不再使用弹窗式大标题。它说明用户此刻要判断什么。

### 4.2 决策原文

现有 `context.decisionFraming` 是面积最大的内容区，表示 assistant 在最终问题之前给出
的判断背景、方案比较和约束。它保留换行并允许选择复制，不得只显示成单行摘要或
小型上下文预览。没有 `decisionFraming` 时不伪造内容，也不显示空标题。

### 4.3 用户回答

回答紧随原文，以强调色文字显示，但不使用高饱和实心卡片。

### 4.4 问题相关上下文

`context.taskBackground` 默认显示紧凑预览；展开后在同一正文滚动区显示完整任务背景。
上下文截断时保留现有提示。展开不得把底部操作挤出窗口。决策原文已经直接展示时，
上下文组件不得再重复显示相同的 `decisionFraming`。

## 5. 透明毛玻璃系统

毛玻璃不是候选页的独立皮肤，而是所有窗口模式共享的基础材质。

### 5.1 窗口基础

- Electron 窗口继续使用透明背景；
- macOS 继续启用系统 vibrancy，CSS 同时提供 `backdrop-filter` 和
  `-webkit-backdrop-filter`；
- `.app-shell` 与 `.island-body` 使用同一组玻璃窗口 token；
- 窗口背景必须保留足够 alpha，让桌面颜色和明暗边界经过模糊后仍可辨认；
- 只使用轻微主题染色、高光边缘和阴影塑造边界，不用接近纯白或纯黑的实心底遮盖
  vibrancy。

### 5.2 材质层级

统一四级材质，而不是每个组件各写一套透明度：

1. **window glass**：整个窗口的基础透色和模糊；
2. **toolbar glass**：顶部与底部工具栏的轻微区分；
3. **surface glass**：设置卡片、上下文、输入框和次级区域；
4. **raised glass**：悬停、选中、主次按钮和错误状态。

子表面不得通过多层高 alpha 白色背景叠加成不透明块。边框使用低对比度高光与暗边，
阴影只负责从桌面背景中分离窗口。

### 5.3 主题一致性

- **Auto**：跟随系统外观，并与对应 Light/Dark token 完全一致；
- **Light**：低乳白染色、清晰暗色文字；顶部高光不能形成白色实心蒙层；
- **Dark**：略强的深色染色、清晰浅色文字；仍保留桌面透色，不退化为不透明深灰；
- 主题切换只替换 token，不改变组件结构、边距、边框宽度或模糊半径；
- 设置页、普通面板、理由岛和待处理页使用同一材质层级，避免某一页透明、另一页实心。

### 5.4 可读性与降级

- 文本、错误、禁用状态和键盘焦点在浅色与深色桌面背景上都清晰；
- 不对文字节点本身应用滤镜；
- 系统 vibrancy 不可用时，以相同半透明 token 和 CSS blur 降级；
- blur 不可用时仍保留有足够对比度的主题染色和边框，不出现透明到无法阅读的窗口。

## 6. 状态优先级

窗口显示优先级调整为：

1. 设置页；
2. 当前待处理会话临时进入的理由项；
3. 待处理当前项；
4. 其它普通理由项；
5. 空闲隐藏。

该优先级保证记录后能立即补充刚刚提升的该项理由，而不是先显示无关的既有理由项；
其它理由项继续保留。处置该项后恢复连续待处理。

## 7. 数据与隐私

- 未确认候选仍只存在于私有 candidate spool 和内存，不写入 Obsidian 或 SQLite；
- 忽略后删除正文，只保留无正文去重回执；
- 确认后沿用正式理由与 Markdown 写入流程；
- 连续会话只保存 UI 导航状态，不复制候选正文到新的持久层；
- 原文和上下文仍遵守现有长度、摘录和权限限制。

## 8. 测试与验证

### 8.1 行为测试

- 两个及以上候选时，忽略第一项后窗口保持打开并显示第二项；
- 确认第一项后进入其理由流程，完成、跳过和稍后补充都返回第二项；
- 最后一项完成后窗口隐藏；
- Escape 和“稍后”保留当前项；
- 保存失败停留原项，重试成功后继续；
- 会话期间新增候选更新总数并进入队尾。

### 8.2 文案与无障碍

- 菜单、设置、页面和 aria 标签不再出现“待确认候选”；
- `待处理 X / N` 随队列推进更新；
- 键盘焦点顺序为“稍后”→上下文→“忽略”→“记录并补充理由”；
- Escape、按钮禁用和错误提示保持可访问。

### 8.3 布局

- 560 × 640 下工具栏与操作栏固定，原文区获得主体高度；
- 长原文、长项目名、展开上下文和错误状态不遮挡操作；
- 内容可选择复制，滚动只发生在正文区；
- Light、Dark 主题尺寸和空间分配完全一致。

### 8.4 毛玻璃视觉验收

在 Auto-Light、Auto-Dark、Light、Dark 四种状态下分别检查设置页、理由岛和待处理页：

- 把窗口放在同时含明暗区域和颜色块的桌面背景上，能看到背景经过模糊后的色彩变化；
- 窗口不是纯白、纯黑或不透明灰色矩形；
- 工具栏、内容和子表面有层级，但不形成多层实心卡片；
- 文字、按钮、焦点环、错误与禁用状态清晰；
- 吸顶理由岛和普通面板的玻璃质感一致；
- 主题切换后不残留上一主题颜色。

### 8.5 工程验证

- 候选队列、控制器、窗口优先级、Renderer 和 tray 使用 TDD 覆盖；
- CSS token 与布局增加渲染/静态契约测试；
- TypeScript 类型检查、全量测试、构建和 macOS 打包通过；
- 安装新 App 后进行真实桌面背景下的连续队列及主题切换冒烟测试。
